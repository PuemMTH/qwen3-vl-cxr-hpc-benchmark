## จุดที่ควรพูดเมื่อถูกถาม

- **ทำไมเปลี่ยน dataset?** Pilot ครั้งก่อนใช้ 20 ภาพจาก `hf-vision` test split; รอบนี้คัดภาพจากส่วนฝึกของ Mendeley V3 มาใช้ทดลองและปรับวิธี ส่วนทดสอบเก็บไว้ประเมินยืนยันภายหลัง ผลสองชุดไม่ใช่คู่เทียบโดยตรง
- **ทำไม A100 ช้ากว่า?** ผลยืนยันเฉพาะแพลตฟอร์มที่ทดสอบใน batch 1; software stack ต่างกัน จึงยังแยกสาเหตุจากตัว GPU อย่างเดียวไม่ได้
- **ผล 8B BF16 บอกอะไร?** ใน Development 600 ภาพได้ image balanced accuracy 0.4417 และ UNCERTAIN 32.67% ของภาพ; มีผลเฉพาะ A100 จึงไม่ใส่เป็นคู่เทียบ RTX
- **คำทำนายรายภาพบน RTX และ A100 เหมือนกันไหม?** ไม่เหมือนกันทุกภาพ: ต่าง 17/11/19 ภาพสำหรับ 2B/4B/8B NF4 บนภาพ B เดียวกัน 600 ภาพ ผล RTX คัดจาก A ที่ครอบคลุม B และผล A100 A กับ B ตรงกันทุกภาพ; สาเหตุยังไม่พิสูจน์
- **ใช้ GPU มากขึ้นคุ้มไหม?** C2 ลดเวลา inference pipeline ของ workload คงที่ แต่ใช้ GPU-hours ต่อ 1,000 ภาพมากขึ้นเล็กน้อย และยังไม่มี end-to-end turnaround ที่รวมทุกขั้นตอน
- **A100 batch 2 สูงกว่าค่า RTX batch 1 หมายถึงอะไร?** A100 batch 2 จาก C1 ได้ 17,476 ภาพ/ชม. สูงกว่าค่า RTX batch 1 จาก A ที่ 15,545 ภาพ/ชม.; ไม่มีผล RTX batch 2 จึงยังเทียบ batch เท่ากันไม่ได้
- **Median inference pipeline คือเวลาอะไร?** ในแต่ละ batch รวมอ่าน/ย่อภาพ → เตรียม tensor และส่งเข้า GPU → generate → decode/parse; รวมเวลา batch ที่สำเร็จหลัง warm-up ของแต่ละ rank แล้วใช้ rank ที่ช้าที่สุดต่อรอบ ก่อนหามัธยฐาน 5 รอบ (วินาที) ไม่รวมโหลดโมเดลหรือเวลารอคิว
