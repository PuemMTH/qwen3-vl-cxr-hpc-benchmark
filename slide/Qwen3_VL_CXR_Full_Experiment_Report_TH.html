บทสรุป

การทดลองแยกคำถามออกเป็นสี่ส่วน: ความเร็วต่อ GPU (A), คุณภาพและผลของ precision (B), batch scaling (C1) และ multi-GPU scaling (C2) จากนั้นเพิ่ม Set D เพื่อทดสอบ 30B MoE และ 32B dense ซึ่งไม่สามารถโหลดบน RTX 5070 ได้

ผลหลักมีดังนี้

  1. ที่ batch 1 การใช้ A100 หนึ่งใบไม่ทำให้โมเดล 2B–8B เร็วขึ้น RTX 5070 ให้ pipeline throughput สูงกว่าในทุก profile โดย A100 speedup เท่ากับ 0.652, 0.703 และ 0.786 เท่า จึงไม่ผ่านเกณฑ์ 1.5 เท่าทั้งหมด
  2. กฎเลือก comparator ที่กำหนดไว้บน Development เลือก 4b-bf16 ด้วย patient-level balanced accuracy 0.6867
  3. บน A100 การเพิ่ม batch จาก 1 เป็น 8 เพิ่ม pipeline throughput จาก 10,894 เป็น 41,614 images/hour โดยไม่เกิด OOM หรือ parse failure
  4. เมื่อแบ่งข้อมูลและ CPU affinity ถูกต้อง C2 ให้ speedup 1.991 เท่าบน 2 GPUs และ 3.914 เท่าบน 4 GPUs คิดเป็น scaling efficiency 99.53% และ 97.86%
  5. 30B และ 32B เกิด CUDA OOM จริงบน RTX 5070 แต่รันสำเร็จบน 2×A100 บน Development 549 ผู้ป่วย ทั้งสองโมเดลมี balanced accuracy สูงกว่า 4B แต่เพิ่มเพียง 0.0404 และ 0.0468 จึงไม่ถึง margin +0.05 ที่กำหนดไว้ นอกจากนี้ 32B ทำให้ PNEUMONIA recall ลดลง 0.1086 ซึ่งเกินขอบเขต −0.03
  6. งานทั้งหมดใช้ 9.3200 allocated GPU-hours จาก planning ceiling 24 GPU-hours

ข้อสรุปที่ข้อมูลรองรับคือ LANTA มีประโยชน์ด้าน capacity, batching และ parallelism แต่ไม่ให้ความเร็วต่อ GPU สำหรับ workload batch 1 ที่ทดสอบ และยังไม่มี large model ใดผ่าน quality gate ที่กำหนดไว้ งานนี้ไม่ใช่หลักฐานเชิงคลินิกและไม่ใช่ ผล confirmatory

1.4 Metric และกฎการนับ

  • Primary quality metric: patient-level balanced accuracy
  • Metrics เพิ่มเติม: accuracy, macro-F1, uncertainty rate, coverage และ precision/recall/F1 แยกคลาส
  • Patient prediction: strict majority จากทุกภาพของผู้ป่วย; tie, missing, runtime failure และ parse failure กลายเป็น UNCERTAIN
  • UNCERTAIN ไม่ถูกตัดออกจากตัวหารของ accuracy, balanced accuracy หรือ recall
  • ช่วงความเชื่อมั่น: patient-stratified bootstrap 2,000 replicates, seed 20260923
  • Paired comparison: paired patient bootstrap และ exact two-sided McNemar test
  • Throughput ใช้เฉพาะ measured batches ที่สำเร็จและไม่รวม model loading
  • Peak VRAM รวม warm-up; model loading, generation, pipeline และ complete job elapsed แยกรายงานคนละขอบเขต
  • Hardware speedup: local pipeline time / A100 pipeline time
  • Multi-GPU speedup: median 1-GPU inference time / median k-GPU inference time

11. Metric ที่ยังไม่มีหลักฐาน

  • ไม่มี confirmatory Test metric เพราะ Test ยังล็อกอยู่
  • ไม่มี single complete-turnaround timestamp ตั้งแต่เริ่ม stage model จนเก็บผลกลับ local; มีเฉพาะ queue, allocation elapsed, per-round wall และ model-loading time
  • ไม่มี energy consumption, power efficiency หรือค่าใช้จ่ายทางการเงิน
  • C2 ไม่มี confidence interval ของ speedup/efficiency
  • ไม่มี post-Set-D quota snapshot
  • ยังไม่มี multiplicity procedure ที่นักสถิติอนุมัติสำหรับ large candidates สองตัว
  • ไม่มี human HPC operator sign-off, frozen SAP, IRB/privacy determination หรือ confirmatory access authorization
