2. จุดแข็งของ A100 เมื่อเพิ่ม batch และ GPU

โมเดล 4B BF16 เดิมทำงานได้มากขึ้นบน LANTA เมื่อส่งภาพเป็นชุดและเมื่อแบ่งภาพให้หลาย GPU ประมวลผลพร้อมกัน

batch 1, 2, 4, 8 หมายถึงอะไร?

batch size คือจำนวนภาพที่ส่งเข้าโมเดลพร้อมกันในหนึ่งครั้ง ภาพแต่ละใบจับคู่กับ prompt จำแนกภาพข้อความเดียวกัน 1 ชุด แล้วได้ผลทำนายแยก 1 รายการต่อภาพ ไม่ใช่การนำหลายภาพไปรวมใน prompt เดียวเพื่อขอคำตอบเดียว

ภาพ 1 + promptภาพ 2 + promptภาพ 3 + promptภาพ 4 + prompt→model.generate 1 ครั้ง→ผลทำนาย 4 รายการ
batch 1: ครั้งละ 1 ภาพ → 1,000 ครั้งbatch 2: ครั้งละ 2 ภาพ → 500 ครั้งbatch 4: ครั้งละ 4 ภาพ → 250 ครั้งbatch 8: ครั้งละ 8 ภาพ → 125 ครั้ง

จำนวนครั้งข้างต้นคิดต่อการประมวลผล 1,000 ภาพหนึ่งรอบ และไม่รวม warm-up ที่รายงานแยกต่างหาก

3. พื้นที่สำหรับโมเดลใหญ่เป็นข้อได้เปรียบของ LANTA

RTX 5070 มีหน่วยความจำตามสเปก 12 GB ส่วน A100 บน LANTA มี 40 GB ต่อใบ การทดสอบบังคับให้โมเดล 30B MoE และ 32B dense แบบ BF16 อยู่บน RTX 5070 โดยไม่ offload ไป CPU/ดิสก์พบ CUDA out-of-memory ทั้งคู่ ขณะที่รันบน 2×A100 ได้

บนชุด Development 549 ผู้ป่วย โมเดลใหญ่ทั้งสองให้ balanced accuracy สูงกว่า 4B BF16 แต่เพิ่มเพียง 0.0404 และ 0.0468 ซึ่งยังไม่ถึงเกณฑ์ +0.05 ที่กำหนดไว้ และ 32B ทำให้ recall ของ PNEUMONIA ลดลง 0.1086 ดังนั้นความจุที่มากขึ้น เปิดทางให้ทดลองโมเดลใหญ่ แต่ผลชุดนี้ยังไม่รองรับข้อสรุปว่าโมเดลใหญ่ผ่านเกณฑ์คุณภาพ

แหล่งข้อมูลและขอบเขต

  1. รายงานผลการทดลองฉบับสมบูรณ์ — Experiment A, C1, C2, การทดสอบโมเดลใหญ่ และข้อจำกัด
  2. systems-summary.json — ผลรวมที่คำนวณจาก state ของแต่ละรอบ
  3. นิยาม metric และที่มาของ speedup — สูตร, ช่วงเวลาที่วัด และงานที่ตัดออก
  4. โค้ด inference — การจับคู่ภาพกับ prompt, การรวม batch และการแยกผลทำนายรายภาพ
  5. บันทึก SLURM accounting — เวลาส่งงาน เริ่มงาน จบงาน และทรัพยากรที่ใช้

ข้อมูลนี้เป็นผล Development/Pilot ของ workload ที่ระบุ ไม่ใช่ผล confirmatory หรือการจัดอันดับความเร็วทั่วไปของ GPU ทั้งสองรุ่น
